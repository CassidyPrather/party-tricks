# shape-collector

Unity 2022.3 project at the repository root (the "main project", which is the
dev harness) with redistributable VPM packages as directories under
`Packages/`. The VRChat SDK arrives through the vendored bootstrapper on first
editor open and never enters git. Code is AGPL-3.0-or-later with the
VRChat/Unity linking exception in `LICENSE_ADDENDUM`.

## Repo Map

- `Assets/` — the development harness project's own content; nothing shipped lives here.
- `Packages/net.wirenook.shape-collector/` — the package; the prefab and its animator are generated by `Editor/ShapeCollectorBuild.cs`; see README.
- `blender/` — the props' sources, generated by `build_props.py` with the shared kit in wirenook-assets.
- `Packages/com.vrchat.core.bootstrap/` — VRChat's resolver bootstrapper, vendored byte-for-byte. Don't touch.
- `Packages/vpm-manifest.json` — the main project's VPM dependencies (by default the VRChat Avatars SDK, lilToon, and Modular Avatar; NDMF and `com.vrchat.base` are locked as their dependencies). MA and NDMF don't compile without the SDK, because it ships the `System.Collections.Immutable` and Harmony they use. Edit it with a VPM client (ALCOM / `vrc-get`), not by hand.
- `Packages/.gitignore` — allowlist inversion keeping resolver-installed packages out of git. Load-bearing.
- `ProjectSettings/` — pinned Unity project configuration (`ProjectVersion.txt` names the editor build).
- `scripts/` — the checks and builds; CI runs these same scripts, nothing else.
- `.github/workflows/ci-cd.yml` — lint-and-test on push/PR, package publish on release.
- `.githooks/pre-commit` — the fast checks; opt in with `git config core.hooksPath .githooks`.
- `Website/index.html` — placeholder package page; unthemed, unpublished, awaiting a future pass.
- `CREDITS.md` — intake ledger for everything third-party.

This repository is developed inside [cass-avatar](https://github.com/CassidyPrather/cass-avatar), which mounts it and its sibling packages as submodules under `modules/` and opens them all in one Unity project. Generated prefabs and animators are rebuilt from code (`Tools > Wirenook > ...`), never edited by hand.

## Two Targets

The package serves avatars and worlds from one folder, and each side is an
assembly that compiles only where its dependencies are installed
(`versionDefines` that define a symbol per package, `defineConstraints`
that require them).

- `Editor/Wirenook.ShapeCollector.Editor.asmdef` — the avatar side (`ShapeCollectorBuild.cs`). Needs `com.vrchat.avatars`, `nadena.dev.modular-avatar`, `net.wirenook.assets`, `net.wirenook.world-sync`.
- `Editor/World/Wirenook.ShapeCollector.World.Editor.asmdef` — the world side (`ShapeCourse.cs`). Needs `com.vrchat.worlds` and `net.wirenook.skill-checks`. A nested asmdef: the files under `Editor/World/` belong to it and not to the avatar assembly above them.
- `Generated/`, `Models/`, `Prefabs/` — avatar assets. In a world project they import and are used by nothing; the prefab's avatar components are missing scripts there.
- `package.json` depends on `com.vrchat.base` only. Do not add either SDK, or a package only one side uses, to `vpmDependencies`: the other target could then not install it.

Rules:

- **Neither side may reference the other, and nothing may sit outside the two fenced assemblies** that needs an SDK. A third assembly that both use has to be engine-free.
- **The world side has no behaviour of its own.** A course is skill checks: each shape a latched check needing a body contact and the shape before it complete. If it needs something skill-checks cannot do, add it there.
- **`ShapeCourse.Build` does not know the caller's generator.** It makes objects only through `options.Node` and reports every component it adds in `Components`; keep it that way, or generators that sweep what they did not make will undo it.
- **Compile the world side from the world project** (`modules/wirenook-world`: `scripts/world.sh all`), which references this package in place. This repository's own checks never compile it.

## The Course Model

One skinned mesh, `Models/shapes.fbx`: 1,454 triangles (budget 1,500 in `build_props.py`), 26 bones, one material slot. 11 constraints: six hold `Tri`, `Square`, `Circle`, `PostA`, `PostB` and `Sign` on the bus's slots, five are the bus. None of the solid shapes, the gate's lattice, its animation or the posts' lanterns has been seen in VRChat.

- **The gate's lattice is skinned between pairs of bones, `CurtainA`/`CurtainB` and `TeethA`/`TeethB`, one of each pair under each post.** A vertex's share of the `B` bone is how far across the gap it sits. No constraint and no measure of the width. `SPANS` in `build_props.py` and `Spans` in `ShapeCollectorBuild.cs` name the pairs; keep them in step. `blender/README.md` has the modelling rules.
- **`PostA` and `PostB` carry locked constraints and only move, never turn.** Animate bones under them, not them. Geometry that must look right whichever way the gate runs is upright strips or turned about the upright.
- **The lattice is hidden by scaling all four of its bones to zero together** (`SC Gate Bars`). Anything in it weighted to a fifth bone would be left behind as a sliver.
- **A bone under a post that a later layer scales is also scaled by the layer that shows the post** (`SC Gate Left`/`Right` hold the lattice bones and the lantern's `Lamp*` bones at zero; `SC Gate Bars` and `SC Sign *` override). Avatar Optimizer dropped such curves in party-tricks. Unverified here: check a built avatar with `FxProbe.Clips`.
- **The lanterns show the sign's triangle, square and circle but not its tick.** A post is gone by the time the tick would show.
- **The shared prop kit allows one bone per vertex.** `build_props.py` replaces `wirenook_props.assemble` and `_validate_skin` to get shared weights through; a change to either in wirenook-assets has to be carried over.

## The SDK Boundary

- The VRChat SDK and Unity are proprietary; the repository must stay clonable,
  checkable, and testable without either installed.
- `Packages/*/Runtime/Core/` is engine-free C#. `scripts/test.sh` compiles it
  with plain dotnet against NUnit alone, so a `using UnityEngine` in Core is a
  CI failure, not a style nit. Engine and SDK glue lives outside Core and is
  exercised in the editor instead.
- Tests use classic NUnit asserts only: the same files must pass `dotnet test`
  and the editor's Test Runner, and the classic API is the overlap.
- Never weaken the `Packages/.gitignore` allowlist; it is what makes committing
  non-redistributable material structurally impossible.

## House Rules

- Every asset gets a `CREDITS.md` line at intake — source, author, license, URL. CC0 first.
- Nothing proprietary and nothing licence-incompatible enters this repository; generate or draw it instead.
- Unity editor stays on 2022.3.22f1, the version VRChat supports. Runtime Unity packages in `Packages/manifest.json` (Timeline, TextMeshPro, AI Navigation, uGUI) stay at the versions the VRChat client ships. Only editor-only tooling (IDE integrations, Test Framework) tracks the latest.
- Version lives in `package.json`; a release publishes every package whose version matches the tag.
- The linking exception in `LICENSE_ADDENDUM` is load-bearing legal text. Don't reword it casually.
